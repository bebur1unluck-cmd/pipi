# Модель системы заказа и учета товаров в бакалейной лавке

## Назначение системы

Система предназначена для ведения справочников товаров и поставщиков,
контроля остатков на полках бакалейной лавки, формирования заказов
поставщикам и печати справочной информации по запросу пользователя.

## Основные пользователи и внешние объекты

- **Пользователь системы**: товаровед, продавец или владелец лавки,
  который ведет учет, оформляет заказы и печатает отчеты.
- **Поставщик**: фирма, поставляющая товары в лавку.
- **Принтер**: внешнее устройство для вывода отчетов.
- **База данных**: хранилище сведений о товарах, поставщиках, заказах
  и позициях заказов.

## Обрабатываемые данные

### Товар

- наименование;
- место хранения: конкретная полка;
- текущее количество;
- минимально допустимый остаток для определения необходимости пополнения;
- поставщик.

### Поставщик

- название фирмы;
- адрес;
- телефон.

### Заказ

- номер и дата создания;
- поставщик;
- статус;
- набор позиций заказа.

### Позиция заказа

- товар;
- количество товара в заказе.

## Функциональные требования

1. Добавление информации о новом товаре.
2. Изменение информации о существующем товаре.
3. Удаление информации о товаре.
4. Добавление, изменение и удаление информации о поставщиках.
5. Формирование заказа для выбранного поставщика.
6. Добавление нескольких товарных позиций в один заказ.
7. Печать справочной информации:
   - список всех товаров;
   - список товаров, имеющихся в наличии;
   - список товаров, количество которых необходимо пополнить;
   - список товаров, поставляемых данным поставщиком.

## Принятые проектные решения

- Один товар относится к одному основному поставщику, так как в условии
  для каждого товара фиксируется его поставщик.
- Порог пополнения хранится в карточке товара как минимально допустимый
  остаток. Если текущее количество меньше или равно этому значению,
  товар попадает в отчет о необходимости пополнения.
- Заказ создается для одного поставщика и содержит одну или несколько
  позиций. Позиция заказа ссылается на товар и хранит заказанное количество.
- Удаление поставщика допустимо только при отсутствии связанных товаров
  и заказов либо после их переназначения/архивации.
- Печать отчетов выполняется через отдельный сервис печати, чтобы
  бизнес-логика учета не зависела от конкретного устройства.

## Состав файлов с диаграммами

- `idef0_context.drawio` — контекстная IDEF0-диаграмма A-0.
- `idef0_decomposition.dot` — декомпозиция IDEF0-диаграммы A0.
- `uml_use_case.puml` — UML-диаграмма вариантов использования.
- `uml_class_diagram.mmd` — UML-диаграмма классов в формате Mermaid.
- `uml_order_activity.puml` — UML-диаграмма активности оформления заказа.
- `uml_order_sequence.puml` — UML-диаграмма последовательности оформления заказа.
- `uml_order_state.mmd` — UML-диаграмма состояний заказа в формате Mermaid.

## Как просматривать

- Файл `.drawio` открывается в diagrams.net/draw.io.
- Файлы `.puml` открываются PlantUML.
- Файлы `.mmd` открываются Mermaid Live Editor или средствами Markdown,
  поддерживающими Mermaid.
- Файл `.dot` можно отрисовать Graphviz командой:

```bash
dot -Tpng docs/idef0_decomposition.dot -o docs/idef0_decomposition.png
```
